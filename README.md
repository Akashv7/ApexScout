# Unseen XI — Full Application

A real, running web app: Node/Express backend, JSON-file persistence, a
genuine Elo-style Talent Index computation engine, four working rule-based
AI agents, and a frontend that talks to all of it over a real API —
not mock data.

## Run it

```bash
npm install
npm run seed     # builds data/db.json with starter leagues/players/matches
npm start        # http://localhost:3000
```

That's it — no external database, no API keys, no build step.

## What's genuinely real here

- **Talent Index Engine** (`lib/ratingEngine.js`) — Elo-style team ratings
  updated after every match; player Talent Index computed from performances
  weighted by the *opponent's* rating at the time of that match. Re-run
  `npm run seed` and watch the numbers come out differently if you edit the
  match data — they are computed, not typed in.
- **Persistence** — `data/db.json`. Restart the server; your data is still there.
- **Four working AI agents** (`lib/agents/`), wired into real API routes and
  visible on `agents.html`:
  1. **Talent Index Engine** — described above (`ratingEngine.js`, not in `/agents` but the core one)
  2. **Discovery Agent** — flags "hidden gems": high index relative to league strength
  3. **Verification Agent** — checks stat plausibility per format, can upgrade trust tier
  4. **Scout-Matching Agent** — ranks + explains recommendations for a scout's search
  5. **Moderation Agent** — screens self-submitted bios before saving
- **Full user flows that actually work**: register a player → record a match
  for them on the Admin page → their Talent Index appears, computed live →
  run the Verification Agent on their profile → shortlist them in Scout Zone
  (persists server-side).

## What's honestly still a placeholder

- **Auth** — there's no login system. `scout.html` uses a hardcoded
  `demo-scout` ID; production needs real accounts.
- **Video** — the "match footage" boxes on player profiles are static UI;
  there's no upload pipeline or video-based verification/highlight extraction.
  The Verification Agent only checks number plausibility, not footage.
- **Agents are rule-based, not ML** — deliberately, so they're inspectable
  and debuggable. A production system would likely add a learned model on
  top of these (e.g. an LLM-based moderation pass, computer-vision highlight
  extraction), not replace this logic — see the "Not Yet Built" note on
  `agents.html`.
- **Only Cricket** — the schema (sport + format fields) supports other
  sports; only Cricket pages are built.
- **Elo K-factor / impact formulas are simplified** — documented in code
  comments in `ratingEngine.js`, tuned for demo-scale data, not validated
  against a large real dataset.

## File structure

```
unseen-xi/
├── server.js              Express app entrypoint
├── lib/
│   ├── store.js             JSON-file persistence layer
│   ├── ratingEngine.js      The Talent Index computation engine
│   └── agents/
│       ├── discoveryAgent.js
│       ├── verificationAgent.js
│       ├── scoutMatchingAgent.js
│       └── moderationAgent.js
├── routes/                API endpoints (players, leagues, matches, scout, agents)
├── scripts/seed.js        Builds the starter dataset + runs the engine once
├── data/db.json            Generated by seed — the actual "database"
└── public/                 Frontend (plain HTML/CSS/JS, calls the API via js/app.js)
    ├── index.html            Home / Discover
    ├── cricket.html          Ground vs Turf leaderboards
    ├── player.html            Profile (?id=...) with live Verification Agent trigger
    ├── scout.html             Filters + Scout-Matching Agent + persisted shortlist
    ├── agents.html            Live dashboard of all agents
    ├── register.html          Player self-registration (moderation-screened)
    ├── admin.html              Record a match → watch ratings recompute live
    ├── css/styles.css
    └── js/app.js               API client + shared UI (Talent Index dial, cards)
```

## Suggested next real milestones

1. Add accounts (players, scouts) with actual auth — everything currently
   assumes a single demo identity per role.
2. Swap `data/db.json` for a real database (Postgres/SQLite) once multiple
   people are writing to it concurrently — the JSON file is fine for a
   single-server demo, not for production traffic.
3. Video upload + a real highlight-extraction/verification pipeline.
4. Duplicate the Cricket pages/schema for a second sport (Football is the
   most natural next one) to prove the "sport + format" model generalizes.
